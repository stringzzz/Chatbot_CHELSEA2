############################################################################################
##################### Chatbot CHELSEA message handling algorithm ###########################
############################################################################################
#
# 1. User enters message
#
# 2. Detect if entered command to enable/disable speech recognition mode
#
# 3. Start nmap scan and detect network questions if 'netdancer' argument is enabled
#
# 4. Detect if math question, use external script to handle
# and give solution to question (Highly experimental)
#
# 5. Detect if given 'happy birthday' or birthday related question
#
# 6. Detect if asking what she is or is not
#
# 7. Detect if asking what user is or is not
#
# 8. Detect if telling what she is or is not, learn accordingly
# Also detect if contradiction to what she already knows
#
# 9. Split message into words, remove punctuation
# Determine mood of reply, add counts to CHELSEA mood as well
#
# 10. Mark unknown words in message
#
# 11. Add to counts for each word, adjust the tied emotion to them accordingly
#
# 12. Take each word and associate all other (non-neutral) words in message 
# with them (Either start or add to count)
# Comes into play in matching single associated word with highest count, or select
# one randomly from list of highest
#
# 13. Identify bigrams in the user message and mark as new or add to counts if
# already seen
#
# 14. Identify trigrams in the user message and mark as new or add to counts if
# already seen
#
# 15. Add to running counts of all words in conversation
# Get topic(s) of conversation by the maximum value
#
# 16. Keep track of matching words from 3 previous message/response pairs
# Get list of these 'depth words'
#
# 17. Mark unknown words in dictionary for 'what is/are __' unanswered questions
#
# 18. Check for answer to previous 'what is/are' question
#
# 19. Check for answer to previous 'why is/are' question
#
# 20. Check if user asking for clarification on previous response,
# try to find matching message containing 2 or more words from
# previous response
#
# 21. Check if asking what CHELSEA feels about ___,
# respond according to the tied emotions with the words in ___
#
# 22. Check if asking 'do you like/dislike ___' question
# respond according to tied emotions to words in ___,
# agreement or disagreement depends on emotion and like/dislike
# word used
#
# 23. Check if asking 'which is better, _1_ or _2_'
# Used emotions tied to the words to decide which CHELSEA likes better,
# or indifferent if neither is tied to happy overall
#
# 24. Check if asking 'why is' question, try to find match involving
# 'because' words a possible answer
# 
# 25. Check for 'most __emotion__' question, respond with biggest word(s) tied to emotion
#
# 26. Check if user asking some other type of question not handled by the above methods.
# Attempt to find a fuzzy match of the question in memory with at least 75% similarity,
# then give the response tied to that matching question if so.
#
# 27. Check if missing user birthday information, check if user giving info, 
#	or ask for it
#
# 28. PRNG to see if asking user about their preferences
#
# 29. Confirm if user answering question about their preferences,
# possibly modify user message to let fall through to other methods
# by fitting its format to the patterns
#
# 30. PRNG to see if asking user about their past preferences stored in user file
#
# 31. Confirm if user answering question about their past preferences
#
# 32. Check if user giving details about their preferences, process accordingly
# and store information, possibly further asking 'why' about their preferences
#
# 33. Confirm user's preference information by answering clarification questions
#
# 34. PRNG and if user in 'laughing mood' potentially bring up old response
# user found funny previously
# 
# 35. PRNG, possibly bring up past topic at least a day old
#
# 36. Check for an exact match of message, give linked response if so, 
# may also use recursive fuzzy_match to find a chain of responses given odds 1/N,
# the odds of each getting lower and lower each recursive call, 
# starting at 1/5.
#
# 37. Check if message matches as part of a message in memory,
# give linked reponse if so, 
# may also use recursive fuzzy_match to find a chain of responses given odds 1/N,
# the odds of each getting lower and lower each recursive call, 
# starting at 1/5.
#
# 38. No match, add response to list in message memory or learn brand new message/response pair
#
# 39. Try to find at least 55% similarity (fuzzy) match with the user message to a message in memory,
# and give the reponse tied to the matching message if so.
#
# 40. If certain # or greater messages and words in dictionary, PRNG to
# determine if attempting topic match, or 'depth match' (Coin flip between two) 
#
# 41. Given certain memory conditions and PRNG, search for chain trigrams/bigrams starting with randomly 
# chosen topic or depth word (Coin flip), chain either forward or reverse (Coin flip)
#
# 42. If certain # or greater messages and words in dictionary, PRNG to
# determine if doing single term match. If so, coin flip to determine whether
# trying to match single word from message as part of message in memory,
# or single word associated with word from message. Repond with linked 
# response if so
#
# 43. 1/6 chance asking unanswered question, else respond with random response from memory to keep conversation going
#
